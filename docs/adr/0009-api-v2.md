## Context

The shape of v1 cannot carry the improvements of the rebuild ([ADR 0008](/docs/adr/0008-api-v1-frozen-contract/)). v1 has these problems:

- Values are strings with units.
- v1 leaves out unknown fields, so "missing" and "unknown" look the same.
- It uses the PHP `element[]=` form, whole-eV rounding and the old sort order.
- It has no total count and no paging links.
- It carries EDS metadata that HyperSpy does not need (hyperspy#993).

HyperSpy users asked for the DOI as a structured field (hyperspy#994).

## Decision

- The API host serves `/v2/spectra` and `/v2/spectra/{id}`. The responses have these properties:
  - Numbers are numbers. Field names hold the units (`value_kv`, `_mrad`, `_ev`).
  - Beam energy and angles have provenance. Missing values are `null`.
  - Each spectrum has a type code (`coreloss`), a `technique`, a `phase` and `intensity_units`.
  - The reference is structured and has a separate `doi`.
  - EELS and XAS data are in separate blocks.
  - Each spectrum has a `licence`.
  - Each file has a role, a media type, a size and a SHA-256.
  - Each spectrum lists the tool versions used at review.
  - Lists have `total`, `page`, `per_page`, `next` and `previous`. A page holds 500 spectra at most.
  - An unknown query parameter returns 400 with `unknown_parameter`. A non-numeric paging value returns 400.
- The API uses `@hono/zod-openapi`. The zod schemas in `worker/src/api/v2-schema.ts` do three jobs:
  - They validate queries.
  - They generate `/api/openapi-v2.json`.
  - They check every response in tests with strict objects, so an undocumented field fails.
- The browse page runs on the v2 query (`spectraFilter` / `listSpectra` in `worker/src/api/v2.ts`). It uses the v2 parameter names, so a browse address is a v2 query ([ADR 0030](/docs/adr/0030-browse/)). The metadata harvesting endpoints ([ADR 0026](/docs/adr/0026-metadata-harvesting/)) use the same query.
- Lists include all published spectra, gas phase included. Only v1 hides gas phase, for compatibility ([ADR 0008](/docs/adr/0008-api-v1-frozen-contract/)).
- v2 has these query parameters:
  - `type`, `author` and `phase` can repeat. A spectrum matches if it matches any value.
  - `keyword` matches all values and ignores case.
  - `max_resolution_ev`.
  - `updated_since` and `sort=updated_at`.
  - `sort=author`.
  - The energy filters are "starts at or above", "ends at or below" and "includes".
- `updated_at` returns the "modified" time: `MAX(published_at, COALESCE(updated_at, published_at))`. An edit before publication leaves `updated_at` older than `published_at`.
- `POST /v2/drafts` accepts drafts. It takes multipart data with the field names of the submit form, and it needs a drafts-only token ([ADR 0017](/docs/adr/0017-no-package-drafts-api/)).
- Field names should follow the HyperSpy metadata conventions. They should also follow the HyperSpy 3.0 metadata proposal when it settles. That proposal is hyperspy-proposals#1, "hspy-spec". It defines JSON-Schema metadata with a Source/Detector tree that replaces TEM/SEM.

## Consequences

- One set of schemas means that the docs cannot drift from the code.
- To move from v1 to v2, make these changes:
  - `element[]=` becomes repeated `element=`.
  - `title` becomes `q`.
  - `*_compare` becomes `min_energy_ev` / `max_energy_ev`.
  - `per_page=-1` becomes paging with `next`.
  - `"Core Loss"` becomes `coreloss`.
  - `beamenergy` becomes `acquisition.beam_energy.value_kv`.
  - The results are inside `results`.
  - Missing fields are `null`.

  The API page in the docs has a "Move from v1 to v2" section.
- Withdrawn spectra disappear from v2 lists. `updated_since` cannot show withdrawals, because v2 has no tombstones.
